# Telegram 地址隔离与发件箱安全渲染：待复核

基线：main `e87bbda7f543b3f9b8331d3e1b5bfe56241bd120`。本批只修改仓库，未合并、未部署、未接触生产数据或配置。

## 已核实与修复

- bot 与 Mini App 共用绑定函数：验签后查询 D1 主库，确认 address_id 与地址名同时有效，失败不写 KV。
- 个人邮件推送：KV 地址映射只作路由提示，必须另读取该 Telegram 用户的凭证列表，并核验当前 D1 地址身份。旧凭证、已删除/转让/同名重建地址不授权推送。管理员全局推送配置语义保持原样。
- Mini App 绑定列表：过滤失效地址凭证。
- 解绑：仅更新调用者自己的凭证列表，不删除地址路由提示。原因是 KV 不支持原子 compare-and-delete；先比较再删除仍可能删掉并发的新绑定。残留提示不能单独授权推送。
- 管理员删除：保留已有 D1 原子删除；成功后尽力从映射用户列表移除被删除 address_id 对应的 JWT，清理失败仅记录固定事件，不让已完成的删除返回失败。新 id 的同名凭证保留。
- 发件箱桌面、手机详情：均使用已有 ShadowHtmlComponent；纯文本、源码视图不变。无 Shadow DOM 的回退额外禁止 style 标签，防止全局样式污染。邮件原文不修改。

## 保留风险与兼容性

- 普通解绑没有使地址 JWT 失效；KV 用户列表传播仍可能延迟，不能承诺即时停止所有区域推送。删除/转让造成 id 变化的场景由 D1 身份检查阻断。KV 并发读改写用户列表仍可能丢更新；本轮没有增加强一致存储或迁移表结构。
- 路由提示有意保留，避免非原子清理误删新绑定；未来若需要即时解绑或映射回收，需独立评估强一致登记方案。不要把这项标成“KV 全部清理完毕”。
- 现有全局推送管理员权限保持不变。不含当前有效 address_id 的旧凭证不再支持个人推送。
- 发件箱的 active HTML 被清洗；脚本、表单、iframe 等内容会被移除，正常正文、链接、图片维持现有清洗规则。
- 依赖漏洞、JWT 全面到期、密码体系、OAuth、日志全面治理不在本批。
